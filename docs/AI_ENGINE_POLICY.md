# AI Engine Policy & Privacy Specification

This document defines CompressZ's policy and technical implementation for client-side Artificial Intelligence (AI) and Machine Learning (ML) inference.

---

## 1. Core Principles

1. **100% Client-Side Local Execution**: All AI/ML models run strictly inside the user's browser runtime. At no time are model inputs (prompts, images, documents, audio) or outputs transmitted to external servers, cloud inference APIs, or third-party platforms.
2. **Deterministic & Stateless**: Model runs do not maintain persistent memory or conversational state across sessions. When an AI task completes, memory buffers are unmapped and garbage-collected.
3. **No Training or Model Telemetry**: User data processed by AI engines is never used for model training, reinforcement learning, fine-tuning, or feedback loops.
4. **Transparent Resource Governance**: AI workloads are strictly throttled and monitored by the Adaptive Resource Guard to prevent device overheating, out-of-memory (OOM) browser crashes, or thread starvation.

---

## 2. Supported AI Frameworks & Runtime Backends

CompressZ uses open-source, standards-based browser machine learning runtimes:

| Framework | Primary Task | Supported Backends | Fallback Backend |
| :--- | :--- | :--- | :--- |
| **Transformers.js** (`@huggingface/transformers`) | English handwriting recognition, document understanding | WebGPU (`navigator.gpu`) | WebAssembly SIMD (`cpu`) |
| **ONNX Runtime Web** (`onnxruntime-web`) | OCR text detection & CJK recognition (PaddleOCR), background removal | WebGPU / WebGL2 | WASM Multi-threaded SIMD |

### 2.1 Backend Selection Policy
- **Preferred Backend (WebGPU)**: When `navigator.gpu` is available and compatible, CompressZ dispatches compute shaders to the local GPU hardware via WebGPU. This provides high throughput without locking the main thread.
- **CPU Fallback (WASM SIMD)**: When WebGPU is disabled, unavailable, or restricted by permissions, the runtime automatically falls back to 128-bit SIMD WebAssembly executing in dedicated Web Workers.

---

## 3. Model Weight Acquisition & Caching Policy

1. **On-Demand Fetching**: Model weights are not bundled with the static initial application download to preserve fast startup. They are fetched on first tool invocation only when the user selects a feature that requires an AI model.
2. **Public CDN Sources**: Weights are fetched via HTTPS from verified public CDNs (e.g., Hugging Face Model Hub, jsDelivr, Cloudflare CDN) as immutable, read-only ONNX / SafeTensor binaries.
3. **Local CacheStorage**: Once downloaded, model weights are stored in the browser's persistent `CacheStorage` or `IndexedDB`. Subsequent runs execute completely offline without network access.
4. **Cloudflare Pages Asset Stripping**: Models or WASM assets exceeding Cloudflare Pages' 25 MiB static file hosting limit are isolated and fetched on demand from configured CDN endpoints (`scripts/strip-oversized-assets.mjs`).

---

## 4. Privacy Boundaries

- **Zero Remote Prompts**: CompressZ does not interface with proprietary LLM APIs (OpenAI, Anthropic, Google Cloud AI).
- **Ephemeral Input Buffers**: Images and tensors loaded into WebGL/WebGPU textures are freed immediately after tensor output generation.
- **No File Logging**: Debug logs generated by ONNX Runtime or Transformers.js are suppressed in production builds to prevent accidental leaking of tensor dimensions or document properties into developer tools.

---

## 5. Memory Management & Lifecycle

- **Concurrency Capping**: The AI engine enforces concurrency bounds via `resourceManager.ts`, allowing at most 1 heavy model execution at a time.
- **Disposal**: When switching tools or clearing file queues, model sessions expose `.dispose()` or `.release()` calls to return allocated WebGL/WebGPU contexts and WebAssembly heap back to the host operating system.
